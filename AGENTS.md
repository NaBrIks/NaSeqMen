# NaSeqMen — правила проекта

## Переход к самоописанному графу — решение владельца 2026-11-16

Владелец поручил зафиксировать текущую версию тегом `v0.0.1` и подготовить план для другого исполнителя. План и критерии приёмки: [docs/plans/self-describing-graph.md](docs/plans/self-describing-graph.md). Реализация новой модели в этой контрольной точке ещё не выполнена.

Для новой модели обязательные слои `Source/Event/Action/Destination` отменены. Это возможные категории оформления. Узлы и адаптеры самоописывают порты, типы, свойства, методы, события и возможности; граф допускает C#-обработчики, несколько выходов и вложенные узлы. Соответствующие требования фиксированных слоёв ниже и в документах альфы относятся к прежней реализации. Универсальность, независимость исполнителя от редактора и правила работы с действующим AHK сохраняют силу.

## Универсальность продукта — прямое указание владельца от 2026-11-16

- Разрабатывать только общие механизмы для всех поддерживаемых устройств и сценариев. Запрещены реализации и прототипы, заточенные под оборудование владельца, один экземпляр устройства, кнопку, сочетание или персональную схему.
- Правило распространяется на ядро, исполнитель, редактор, модули, драйверы, сборки и встроенные профили. Запрещено зашивать в них конкретные VID/PID, интерфейсы, Instance ID, привязки кнопок, сочетания и действия ради одного пользователя или одного тестового стенда. Сборка одна для всех пользователей.
- Обнаружение использует общий контракт, а выбор экземпляра, интерфейса, события и действия хранится в пользовательской конфигурации. Общий механизм может выполнять правило для одного выбранного экземпляра. Оборудование владельца допустимо использовать для локальной проверки этого механизма. Не переносить идентификаторы стенда в поставляемый код и примеры.

> Уточнение владельца 2026-11-15: текущее состояние удерживаемых клавиш, включая Shift/Ctrl/Alt/Win, разрешено для условий и обработки. Это узкое исключение из прежнего запрета состояний, без истории и дискового хранения. Контракт и текущая граница реализации: [состояние ввода](docs/input-state.md).

Рабочее название: NaSeqMen. Самостоятельный коммутатор событий, значений и действий. NaSDock — независимый пульт и одна из интеграций.

## Обязательные границы

- Primary language is English. All built-in user-facing strings in the active HTML/WebView editor, executor and modules must use stable resource keys, with English and Russian catalogs. Never use translated prose as a key or infer translations from message text. Preserve user-authored names, scripts and external messages. UI language is selected with EN/RU and defaults to English for a new profile. Read docs/localization.md before adding UI copy or diagnostic messages.

- В коммутаторе нет общего хранилища последних значений, истории, восстановления, replay и автоматической начальной синхронизации. Узкое разрешённое исключение — текущее состояние удерживаемых клавиш модуля ввода для условий и обработки: docs/input-state.md. На диск сохраняется конфигурация: соединения, сопоставления, схемы, исходники сценариев и настройки.
- Исполнитель и редактор — отдельные процессы. Исполнитель работает без редактора в пользовательском сеансе; редактор соединяется через API. Ввод и выполнение не зависят от открытого UI.
- Модули законченные, отдельные подпроекты/пакеты. Общий экземпляр соединения используется входами и выходами. OBS — первый пример, не часть ядра.
- Простые действия выбираются в UI; пользовательские обработчики/макросы потенциально пишутся на C# и получают окружение исполнителя.
- Пробный прогон показывает сформированные выходы, не симулирует фактический результат внешней программы. Произвольный C# с прямыми внешними вызовами не считать автоматически безопасным для такого прогона.
- Код AutoHotkey и AutoHotInterception не копировать, не переводить и не адаптировать. KOE.ahk — только поведенческий образец. Для временного захвата допускается подключение уже установленного Interception через его опубликованный ABI. DLL и драйвер не входят в проект.
- Интерфейс плотный, русскоязычный, свободно изменяемого размера. Схема с вертикальными полосами и связями прямо запрошена владельцем; списки — таблицы с фильтрацией и сортировкой, редактирование — компактные окна. Никаких фиксированных размеров под модель мыши, декоративных карточек, баннеров/toast и скачков геометрии.
- Диагностика живая на каждом этапе. Технические идентификаторы допустимы в режиме изучения устройства; обычная схема использует пользовательские имена.
- Поток UI слева направо: источники, события, условия, обработка, действия, получатели. Роль узла выбирается при создании. Редактор существующего узла показывает форму его роли без выбора слоя. API сохраняет роль существующего идентификатора. Получатели отображаются по метаданным действия и его соединению.
- Конечный выбор в форме показывать радиокнопками. В частности, enum, фазы и типы портов из двух–четырёх значений всегда видны сразу. Для длинных каталогов использовать прокручиваемый список выбора. По указанию владельца каталог загруженных плагинов показывать отдельным выпадающим списком.

## Совместная работа

- Organize code by responsibility in named folders. Aim for 300–500 lines per source file. Above 500, check for a meaningful split into components or partial classes. Files approaching 1000 lines need a specific justification.

Подагентам назначать отдельные файлы, не давать одновременно редактировать один файл. Корневой агент сводит архитектуру и устраняет противоречия. Новому чату передавать docs/plans/handoff.md и текущую границу первой альфы. Исправления владельца имеют приоритет.

Локальные сведения об устройствах и личных сценариях — в local/, не в публикуемых примерах. Самостоятельно написанный код — MIT с SPDX; сторонние материалы сохраняют исходную лицензию.
