# Локализация встроенных сообщений

Основной язык продукта — английский. Встроенные названия модулей, операций и типов интерфейсов, проверки конфигурации, диагностические сообщения и ошибки модулей используют стабильные ключи из `src/NaSeqMen.Contracts/messages.json`. Каталог содержит одинаковые наборы ключей и именованных параметров для `en` и `ru`. Русский текст не используется для распознавания сообщения или поиска перевода.

`GET /api/localization` исполнителя требует обычный API-token. HTML-host проксирует этот путь с тем же Origin/Host-контролем, что и другие API; браузеру token не передаётся. Ответ:

```json
{
  "en": { "runtime.conditionPassed": "Condition passed" },
  "ru": { "runtime.conditionPassed": "Условие выполнено" }
}
```

Имена в `ModuleDescriptor`, `OperationDescriptor` и `DeviceDescriptor` имеют английское поле `name` и необязательное `nameKey`. Клиент выбирает `catalog[language][nameKey]`, при отсутствии перевода использует английский каталог, затем `name`. Ключи встроенных описаний имеют вид `module.windows.input`, `operation.obs.startRecord`, `device.keyboard`.

Диагностика и результаты действий сохраняют прежнее поле `message` с английским текстом. Добавлены `messageCode` и `messageArgs`. Неизвестный клиент продолжает читать `message`; новый форматирует выбранный шаблон по коду:

```json
{
  "message": "Route to My button",
  "messageCode": "runtime.routed",
  "messageArgs": { "node": "My button" }
}
```

Результат проверки конфигурации содержит `valid`, прежний массив `errors` и дополнительный массив `issues`. Каждый элемент `issues` имеет `{code,args,message}`. `errors` — английские тексты тех же issues, не отдельный набор ошибок. API-ошибки используют `{code,args,message,error}`, где `error` сохраняет английский текст для прежнего клиента.

Аргумент может содержать вложенное `{code,args,message}`: это известная причина внутри сообщения о недоступном соединении или модуле. Клиент форматирует такие аргументы рекурсивно. Обычные строковые аргументы вставляются как данные и не проходят повторное распознавание шаблонов. Это сохраняет имена с фигурными скобками и предотвращает перевод пользовательского текста по совпадению.

Пользовательские имена узлов/соединений/сопоставлений, payload, текст `Context.Trace`, комментарии внешних протоколов и сообщения ОС сохраняются как есть. Для неизвестного исключения используется код `error.external` и строковый `args.detail`. Ошибки Roslyn имеют код компилятора и английский текст независимо от языка ОС; окружающее сообщение `runtime.scriptCompile` переводится по каталогу.

Метаданные известных исключений передаются через `MessageCatalog.FromException`. В местах, где тип исключения входит в существующее поведение (`IOException`, `ArgumentException`, `AggregateException`), тип сохранён; код и аргументы присоединены отдельно. Это не меняет правила обработки, события и действия.

Нативная поверхность запуска WebView2 имеет отдельные стандартные `.resx` EN/RU: `DesktopText.resx` и `DesktopText.ru.resx`. До загрузки HTML используются английские ресурсы, независимо от языка ОС; настройки browser storage нативный контейнер напрямую не читает. Русская раскладка ресурсов доступна для явного выбора культуры в контейнере, новый переключатель языка запуска не добавлен. Старый WPF UI этим изменением не переписан.

`NaSeqMen.Contracts` теперь имеет переносимую цель `net11.0`, чтобы общий каталог мог использовать и web-host. Windows-исполнитель, модули и окна остаются `net11.0-windows`. При установке требуется согласованная пересборка исполнителя и модулей: изменены сигнатуры DTO-конструкторов. Конфигурации пользователя преобразовывать или переводить не требуется.

## Проверка

`tests/NaSeqMen.LocalizationChecks` выполняет 23 проверки: совпадение ключей/параметров EN/RU, английский fallback, вложенные причины, сохранение пользовательских значений, сериализация DTO, именованные описания всех трёх модулей, диагностический код условия, структурированные validation issues, оба набора нативных ресурсов и английская диагностика Roslyn при русской UI culture.

В изолированной сборке `artifacts/localization-build` прошли сборка решения без предупреждений/ошибок, 21 RuntimeChecks и 37 ModuleChecks. Модульные проверки используют поддельный OBS и клавиатурный backend; реальные SendInput, запуск программ и захват ввода не выполнялись.

Изолированные moduleless-исполнитель на 17967 и proxy на 17968 подтвердили ещё 6 API-проверок: выдачу полного каталога, structured validation, код отказа некорректного синтетического события без принятия события, проксирование каталога, отсутствие token и неизменность конфигурации. Оба тестовых процесса завершены; свидетельство — `local/localization-api-20261115-192216/results.json`. Рабочие процессы и `local/config.json` владельца не изменялись.
