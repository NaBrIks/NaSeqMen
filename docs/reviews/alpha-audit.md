# Независимая архитектурная проверка первой альфы NaSeqMen

15 ноября 2026 г. Исторический срез параллельной реализации с уточнением владельца и повторной статической сверкой контрактов. Проверка опирается на [правила проекта](../../AGENTS.md), [требования владельца](../../REQUIREMENTS.md), [контракт альфы](../alpha-contract.md), [исполнитель и C#](../runtime-and-scripting.md), [модули и ввод](../modules-and-input.md), [редактор](../editor.md) и [стандарт UI](../ui-principles.md). При повторной сверке также прочитаны [README](../../README.md) и [сводная архитектура](../architecture.md). Сборки, процессы, оборудование и окно редактора в рамках аудита не запускались.

## Что согласовано

- Сохраняется конфигурация. В контракте отсутствуют API последних значений, снимок внешнего состояния и replay. Текущий [DiagnosticHub](../../src/NaSeqMen.Runtime/DiagnosticHub.cs) использует ограниченные очереди существующих подписчиков. Новый подписчик получает пустую очередь. Это временная доставка диагностики. В первоначальном срезе маркер потерь появлялся при следующей публикации, поэтому потеря в конце всплеска могла остаться невидимой. Последующее исправление зафиксировано в отчёте интегратора ниже.
- Отдельные проекты Executor и Editor, локальный HTTP API и отдельный диагностический WebSocket согласованы с требованием независимой работы. По сообщению из основного чата проекта прошли сквозные проверки условий, подавления действий и отсутствия replay. Результаты проекта сводятся в `docs/verification.md`. Независимая проверка работы без редактора в этом аудите не выполнялась.
- [INaModule](../../src/NaSeqMen.Contracts/Contracts.cs) предоставляет вход через общий host, условия, действия и жизненный цикл именованного соединения. Этого достаточно, чтобы OBS использовал один экземпляр транспорта в обе стороны. Загрузка DLL, жизненный цикл и поведение самого OBS-модуля требуют проверки после появления реализации.
- [ScriptCompiler](../../src/NaSeqMen.Scripting/ScriptCompiler.cs) готовит настоящий обработчик Roslyn C# с Input и Context. Окружение для первой альфы минимально. В текущих доступных исходниках нет зависимостей на AutoHotkey/AutoHotInterception. Происхождение всех итоговых модулей по этому срезу не установлено.
- [RawInputMonitor](../../modules/NaSeqMen.Input.Windows/RawInputMonitor.cs) заявляет пассивное наблюдение и декодирует клавиатурные и мышиные события, включая отдельные down/up. Политика map в контракте меняет имя сообщения для графа. В Windows оригинал продолжает действовать. В интерфейсе стоит употреблять «Сопоставить» или «Дать имя», чтобы не смешивать эту операцию с системным переназначением R15.
- Владелец уточнил направление схемы. Поток от источников к действиям идёт слева направо. [GraphView](../../src/NaSeqMen.Editor/GraphView.cs) уже рисует контакты, стрелки и принимает жест протягивания провода. Переориентация была в работе на момент повторного просмотра.

## Замечания, закрытые в контракте и исполнителе

- **Пробный прогон C#.** В ActionResult добавлен Suppressed. Общая граница исполнения возвращает Success=false и Suppressed=true до вызова модуля. Сценарий через Context.EmitAsync получает отдельный признак отсутствия внешнего результата. Прямые внешние вызовы произвольного C# по-прежнему вне этой гарантии. Формулировку в редакторе следует сверить при визуальной приёмке. [Контракт](../../src/NaSeqMen.Contracts/Contracts.cs), [реализация](../../src/NaSeqMen.Runtime/GraphRuntime.cs).
- **Типы контактов.** Добавлены InputType, OutputType и общий PortTypes. Executor проверяет совместимость при валидации схемы и тип значения во время обработки. Проверка интерактивной обратной связи редактора остаётся в приёмке. [Контракт](../../src/NaSeqMen.Contracts/Contracts.cs), [реализация](../../src/NaSeqMen.Runtime/GraphRuntime.cs).

## Замечания в историческом срезе

1. **Изучение составного устройства пока сводится к интерфейсам.** В DeviceDescriptor есть Id, Kind и HardwareId, но нет подтверждённой связи интерфейсов с физическим экземпляром. В текущем RawInputMonitor путь именует интерфейс. При ошибке получения пути возвращается временный handle. Сопоставление Source + Control может хранить выбор интерфейса, однако не описывает принадлежность мышиной и клавиатурной частей одному экземпляру. Альфе подходит явное объединение выбранных интерфейсов пользователем при отсутствии надёжного системного идентификатора, с сохранением устойчивых селекторов. VID/PID и временный handle для автоматического применения профиля недостаточны. Перечисление HID-интерфейса отдельно от поддержки его событий должно быть видно в UI.
2. **Подсветка провода после остановки ветви.** В проверенном срезе GraphView считал провод активным по подсветке исходного узла. Этого недостаточно при условии с blocked или при ошибке. Подсветка должна опираться на прохождение конкретной ветви либо на диагностический этап, который однозначно разрешает переход по исходящим связям. Отдельно проверить узкое окно. Внутри GraphView используется минимум 640 для расчёта содержимого и ClipToBounds. Без прокрутки или учёта этой ширины родительским контейнером крайняя правая полоса действий после переориентации может обрезаться. При сильном уменьшении Zoom высота блока уменьшается, а позиция и размеры текста сохраняются, поэтому строки требуют визуальной проверки на нижней границе масштаба.
3. **Формулировки о границах альфы.** README и сводная архитектура уже обозначают WPF, .NET и loopback API как технические решения первой альфы. В первоначальном срезе часть обзорных документов описывала этап до реализации. При сведении документов нужно учесть новое направление схемы и явно оговорить в контракте исключение для loopback GET /api/health без token.

Результаты относятся к NaSeqMen 0.1.0-alpha от 15 ноября 2026 г. Источник — [отчёт о проверках](../verification.md). В рамках аудита запуски не повторялись.

|---|---|
| Исполнитель, API и C# | 32 успешные проверки HTTP, WebSocket, тестового модуля и C#. Executor работает при закрытом редакторе. Новый подписчик получает только новые события. Пробный прогон возвращает Suppressed и оставляет вызов модуля невыполненным. Несовместимые типы контактов отвергаются. |
| Маршрутизация и диагностика | 21 успешная проверка Runtime. Событие routed указывает оба узла фактического перехода, включая NextNodeId. Заблокированное условие не вызывает исходящего перехода. Маркер пропуска выдаётся и после конца всплеска. Проверены запуск с недоступным соединением и повторная попытка по явному сохранению. |
| Редактор | Источники слева, действия справа. Проверены снимки WPF при 1280×820 и 900×600 и финальный снимок с подключением к реальному API. Длинные связи обходят посторонние блоки. Полный ручной проход по модальным окнам и перетаскиванию остаётся открытым. |

По отчёту интегратора исходники AHK не использованы, действующий AHK не затронут. |
| Ограничения | Raw Input наблюдает события отдельных интерфейсов. Физическая группировка составных устройств, подавление ввода, NaSDock USB и изоляция произвольного C# остаются за рамками проверенной альфы. |

## Минимальная приёмка первой альфы

| Проверка | Наблюдаемый результат |
|---|---|
| Два процесса и применение настроек | Executor запускается отдельно. Синтетический сигнал проходит при закрытом Editor. Editor управляет конфигурацией через API. Некорректный граф или ошибка компиляции C# возвращают ошибку, предыдущая конфигурация продолжает работать. |
| Подключение и переподключение | Клиент видит конфигурацию и новые диагностические события. Поступления до подписки не появляются. Медленный клиент не останавливает обработку. OBS при подключении или восстановлении транспорта не запрашивает снимок значений и не воспроизводит старые команды. |
| Один экземпляр OBS в обе стороны | Команда уходит через имя соединения. Новое входящее событие с тем же ConnectionId проходит вторую цепочку. Подтверждение команды коррелируется с конкретным вызовом. Проверка на имитаторе подтверждает контракт. Проверка с реальным OBS нужна, чтобы заявить совместимость с ним. |
| C# и пробный режим | Обработчик компилируется из пользовательского исходника и выполняется с Input и Context. Обычный action и Context.EmitAsync в dry run видны с аргументами и Suppressed. Проверочный модуль не получает ExecuteAsync. Редактор не показывает внешний успех и объясняет, что прямые вызовы произвольного C# могут иметь побочные эффекты. |
| Изучение ввода | Для выбранной составной мыши видны клавиатурный и мышиный интерфейсы, упорядоченные down/up и многострочная последовательность кнопки. Пользователь сохраняет сопоставление как конфигурацию, и оно появляется в схеме. Observe и map оставляют исходное поведение Windows. Suppress явно отклоняется при валидации и не предлагается как доступная возможность. |
| Плотный UI и схема | Поток слева направо. Источники слева, действия справа. Связь создаётся перетаскиванием, несовместимость типов видна, отказ условия не подсвечивает выходной провод. При изменении размера и масштаба контакты остаются доступны. Рабочие списки читаются как таблицы с фильтрами и сортировкой. Сохранение и ошибка API не сдвигают сетку и прокрутку. |

## Открытые решения

- Подавление физического ввода, политика неназначенных кнопок и выбор драйвера остаются за пределами Raw Input-альфы. Отдельно нужна политика завершения сгенерированных удержаний при отмене, отключении и смене конфигурации, если первая поставка предлагает раздельные Down/Up. До её проверки составное нажатие и удержание следует описывать как разные возможности.
- Степень изоляции произвольного C# и модулей, долгосрочный формат пакетов, политика совместимости API и устойчивой идентификации устройств остаются открытыми. Текущий механизм C# является доверенным расширением процесса. Для диагностики полезно зафиксировать, считаются ли ответы на запрос OBS отдельным источником графа и какие уведомления поддержаны первой версией.
- Для проверок нескольких интерфейсов, переподключения, реального OBS и стабильной геометрии окна нужны отдельные свидетельства. В рамках этого аудита такие проверки не проводились. Драйвер, AHK, автозапуск и соседние проекты не затрагивались.
