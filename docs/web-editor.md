# HTML-редактор рядом с WPF

Отдельный проект `src/NaSeqMen.Editor.Web` использует ASP.NET Core на .NET 11 и обычные HTML/CSS/JavaScript из `wwwroot`. WPF-редактор сохраняется отдельным приложением. Оба работают с тем же исполнителем и его конфигурацией; HTML-редактор не содержит второй исполнитель и не хранит состояние внешних программ.

## Запуск

Открыть `Start-NaSeqMen-Web.cmd`. Либо выполнить `powershell -File scripts/start-web.ps1`; для проверки без браузера — `-NoBrowser`. Скрипт собирает HTML-редактор, если опубликованного EXE ещё нет, проверяет исполнитель через существующий `start.ps1 -ExecutorOnly`, запускает веб-процесс в фоне и открывает `http://127.0.0.1:17964` в браузере по умолчанию. WPF при этом не запускается и не закрывается. Автозапуск и службы не устанавливаются.

Для обновления HTML-сборки завершить только `NaSeqMen.Editor.Web`, затем выполнить `powershell -File scripts/start-web.ps1 -Rebuild`. Исполнитель и WPF можно оставить работающими. Локальные PID и журналы веб-процесса находятся в `local/web.pid`, `local/web.stdout.log`, `local/web.stderr.log`.

Ручная сборка: `dotnet publish src/NaSeqMen.Editor.Web -c Release --no-self-contained -o artifacts/alpha/web`. Запуск EXE принимает `--root <папка проекта>`, `--port <порт UI>` и `--executor-port <порт исполнителя>`. Значения по умолчанию — 17964 и 17963. Оба адреса всегда `127.0.0.1`; внешнего адреса назначения или прослушивания нет. Порты должны отличаться и находиться в диапазоне 1024–65535; порт 443 запрещён.

## Контракт браузера

Браузер использует относительные адреса `fetch('/api/...')` и WebSocket `ws://127.0.0.1:17964/api/diagnostics` с тем же origin, что и страница. Тело POST/PUT — JSON с `Content-Type: application/json`. Серверные форматы JSON совпадают с исполнителем:

| Путь | Метод | Назначение |
|---|---|---|
| `/web-health` | GET | Готовность самого HTML-сервера |
| `/api/health` | GET | Готовность исполнителя |
| `/api/config` | GET, PUT | Чтение и применение конфигурации |
| `/api/config/validate` | POST | Проверка без применения |
| `/api/modules` | GET | Описания модулей |
| `/api/devices` | GET | Обнаруженные интерфейсы |
| `/api/inject` | POST | Явная подача синтетического события |
| `/api/diagnostics` | WebSocket | Живая диагностика без истории |

API-token читается сервером из `local/api-token.txt` и добавляется только к запросам сервер → исполнитель. Он не помещается в HTML, JavaScript, URL, browser storage или ответы proxy. Корень статических файлов — только `wwwroot`, а не весь репозиторий. Прокси передаёт только перечисленные пути/методы на фиксированный loopback-адрес; произвольные query-параметры назначения и перенаправления не поддерживаются.

HTTP Host должен точно соответствовать `127.0.0.1:<порт UI>`. Переданный Origin должен совпадать с адресом UI; для изменяющих HTTP-методов и WebSocket Origin обязателен. Запросы браузера с cross-site/same-site Fetch Metadata отклоняются, кроме открытия начальной страницы `/` или `/index.html` верхнеуровневой GET-навигацией (`Sec-Fetch-Mode: navigate`, `Sec-Fetch-Dest: document`). Это позволяет открыть редактор по внешней ссылке; исключение не распространяется на API, iframe или чужой Origin. CORS не включается. Эти проверки препятствуют использованию локального редактора посторонней страницей и DNS rebinding; это не граница защиты от уже работающих доверенных локальных процессов.

HTML использует внешние JavaScript-файлы: CSP разрешает скрипты только с собственного origin, без inline-обработчиков. Стили допускают локальные файлы и inline-свойства; изображения — локальные и data URI. Встраивание страницы в чужой iframe запрещено. API-ответы не кэшируются.

Запрос HTTP ограничен 2 МиБ, ответ исполнителя — 4 МиБ. WebSocket пересылает данные частями с противодавлением, ограничивает сообщение 2 МиБ, сериализует отправки и закрытие для каждого направления, переносит close code/reason и завершает обе стороны при разрыве. Диагностика не сохраняется и не воспроизводится новому подключению.

## Проверка backend

`dotnet build src/NaSeqMen.Editor.Web -c Release`, затем `python scripts/check-web-backend.py`. Нужен уже запущенный исполнитель и Python-пакет `websockets`. Скрипт запускает отдельный тестовый HTML-сервер на 17965 и останавливает только его. Выполняет GET, проверку схемы без применения и транспортные проверки WebSocket; не сохраняет конфигурацию и не подаёт события. Действующий исполнитель, OBS, AHK и WPF не перезапускаются.

Подтверждены 28 проверок: чтение четырёх API и HTML-страницы, отсутствие token в ответах, validate текущей схемы, открытие начальной страницы по внешней ссылке без ослабления API/iframe/Origin-проверок, запрет чужих Host/Origin/Fetch Metadata, неподдерживаемых путей и типа тела, ограничения размера HTTP/WS, обязательный Origin для WS, передача close code/reason и неизменность конфигурации. Свидетельства записываются в `local/web-backend-checks-<дата-время>/results.json`; token и содержимое конфигурации туда не выводятся. Эта проверка backend не является визуальной приёмкой HTML-интерфейса.
