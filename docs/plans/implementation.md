# План и приёмка первой альфы

Обновление владельца 2026-11-15: продолжать реализацию подагентами до первой проверяемой альфы. Этот план выполняется, а не является просьбой снова разрешить уже порученную работу.

Итог первого прохода: A0–A7 завершены в границах альфы. Подробные результаты и оставшиеся аппаратные/продуктовые ограничения — в [verification.md](../verification.md). Работающая альфа не означает выполнение всех будущих возможностей модулей.

|---|---|---|---|
| A0 Архитектура | Root + три подагента | Требования, единая архитектура, границы | Нет противоречий решению без хранения состояний |
| A1 Контракты | Root | Общая библиотека, API документ | Все участники используют одни DTO и имена |

## Проверяемые сценарии

1. Исполнитель запускается с локальным примером и пробным режимом; редактор подключается отдельно.
2. Синтетический вход проходит source, условие down, числовое преобразование и подавленное клавиатурное действие. Никаких реальных Ctrl+C при проверке.
3. Up не проходит условие down, выходной модуль не вызывается.
4. C# преобразует вход и может вызвать действие только через тот же gate; ошибка компиляции видна до применения.
5. Ссылка на отсутствующий узел, цикл или неподдерживаемый режим suppress отклоняются.
6. Диагностика показывает signal/node/stage, новый подписчик не получает историю.
7. При закрытом редакторе исполнитель работает; перезапуск загружает только конфигурацию, не события/значения.
8. Устройства перечисляются; режим наблюдения не подавляет ввод. Сопоставления сохраняются и применяются к дальнейшим сообщениям.
9. OBS mock проверяет авторизацию, запросы, ответы и события. Отдельный настоящий OBS проверяется только безвредными запросами.
10. Пробный режим не вызывает выходной модуль и не выдаёт результат как подтверждение внешнего действия.
11. Короткие/длинные названия, ошибки и разный размер окна не ломают плотность и геометрию UI.

## После первой альфы — отдельные решения

Backend адресного подавления ввода и его лицензия; корректная замена KOE при владении устройством; аппаратная интеграция NaSDock через USB; расширение описаний типов/параметров и модульного ABI; независимая изоляция зависающих сценариев; дополнительные внешние протоколы. Они не блокируют проверку текущей альфы и не выдаются за уже реализованное.
