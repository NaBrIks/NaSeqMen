Дата: 2026-11-16. Документ предназначен другому исполнителю. В этом чате подготовлены исходная точка и план. Реализация новой архитектуры ещё не начата.

- Коммит исходной версии: `17a766b`, аннотированный тег `v0.0.1`.

- Тег содержит текущие изменения Discover, цепочек Event/Default, редактора и окна. Запущенная у владельца программа может отличаться от тегированной сборки. Развёртывание не выполнялось при создании тега.

## Принятые владельцем решения

1. Продукт универсален. Все экземпляры оборудования, интерфейсы, кнопки, сочетания, подключения и действия выбираются конфигурацией. Оборудование владельца допустимо использовать как тестовый стенд общей сборки.
2. Основа — самоописание возможностей логических объектов и механизм их соединения. Адаптер публикует типы, операции, свойства, события и поддерживаемые возможности.
3. `Source / Event / Action / Destination` перестают быть обязательными слоями исполнения. Допустимы как необязательные категории каталога и оформления. Проверка связей определяется контрактами портов.
4. Узлы могут иметь произвольное число именованных входов и выходов. Требуются Switch с несколькими выходами и вложенные составные узлы.
5. Сообщения несут данные. Предусмотреть типизированное содержимое и открытые структуры, сопоставление полей и преобразователи, включая локальный C#.
6. Свойства, методы с несколькими параметрами и события имеют разные правила взаимодействия. Их возможности должны быть описаны явно.
7. C# — полноценный способ реализации узла. Простые обработчики пишутся как тело функции. Определение портов и поведения возможно программно. Скрипт компилируется при применении изменений, готовый обработчик используется многократно.
8. Наблюдение и отладка включаются по необходимости для выбранных узлов/портов/связей. Предусмотреть Debug и просмотр содержимого сообщений с привязкой к их прохождению.
9. Interception — один из модулей. Его особенности не должны определять общую модель данных или допустимые виды оборудования.
10. Исполнитель обслуживает подключения и выполняет граф независимо от редактора. WebView2 и браузер используют один HTML-редактор.

Эти решения заменяют прежнее требование фиксированных колонок и закреплённых ролей узлов в документах альфы. Существующие документы описывают старую реализацию, пока соответствующий этап перехода не завершён.

## Предлагаемый контракт для первой реализации

Названия ниже рабочие. Исполнитель уточняет их по коду, сохраняя смысл и минимальный объём первого этапа.

### Описание и экземпляр узла

- Описание типа содержит стабильный ID и версию, параметры, каталог портов, типы сообщений и метаданные представления.
- Экземпляр содержит пользовательские параметры, ссылки на подключения и стабильные ID своих портов.
- Порт описывает направление и семантику: сообщение, вызов с результатом, ссылка на ресурс или обработчик с обязательным завершением.
- Динамический состав портов вычисляется при подготовке конфигурации. Проверка схемы показывает последствия удаления/изменения порта для существующих связей. Обработка входного сообщения не меняет незаметно структуру графа.
- Получение описания узла отделено от открытия внешнего подключения. Редактор получает сериализуемые описания через API исполнителя.
- Модуль описывает свои возможности полностью; конкретный экземпляр дополнительно сообщает доступность операций и объектов.

### Сообщения, вызовы и свойства

- Общая оболочка содержит идентичность сообщения, происхождение, описание содержимого и при необходимости связь запроса с ответом. Предусмотреть различение ветвей прохождения без потери исходного происхождения.
- `Payload` допускает описанную структуру и открытые данные. Схема и версия типа не требуют обязательной генерации отдельного CLR-класса для каждого пользовательского сообщения.
- Один вызов метода получает полный согласованный набор аргументов. Константы берутся из настроек, остальные аргументы — из текущего сообщения или явного преобразования.
- Объединение независимых входных сообщений требует явной семантики согласования. Не вводить скрытые последние значения на всех портах.
- Чтение, запись и уведомление об изменении свойства объявляются отдельными возможностями. Объект может поддерживать только часть из них.
- Ответ вызова и внешнее событие различаются. Ошибку/тайм-аут нельзя выдавать за успешный ответ. Поздний ответ относится к исходному вызову, а не к следующему запросу.
- Для разветвления определить владение данными. Изменение открытого объекта одной веткой не должно случайно менять данные другой ветки. Выбрать и проверить неизменяемые сообщения либо копирование в определённых точках.
- Типизация включает смысловые ограничения и единицы, где они нужны. Преобразователи выбираются явно при неоднозначности.

### Исполнение и ресурсы

- Подключение — общий ресурс. Несколько входных, выходных и вложенных узлов могут использовать один экземпляр.
- Рассылка запускает все подключённые ветки. Switch явно настраивается на первое совпадение либо все совпадения, имеет Default.
- Порядок исполнения определяется связями и описанной политикой, а не положением блока на холсте.
- Предусмотреть ограничение очередей, отмену, ошибки и политику перегрузки. Потеря диагностической строки и потеря рабочего входа — разные ситуации, требующие отдельных правил.
- Для первой версии отклонять мгновенные циклы выполнения. Обратные события внешнего подключения и результаты вызовов проходят по явно описанной модели. Произвольные повторения потребуют отдельной семантики.
- Подготовить новую конфигурацию и скрипты до переключения. При ошибке подготовки сохранить предыдущую рабочую конфигурацию. Для смены подписок/подключений определить завершение старых операций и ограниченное восстановление при частичной ошибке.
- Обработка удерживаемых клавиш и текущих незавершённых операций допускает локальное временное состояние. Общее хранилище последних значений, replay и автоматическая синхронизация не вводятся.
- Пробный режим действует на внешние вызовы через окружение исполнителя. Произвольный доверенный C# сохраняет возможность прямых внешних вызовов; интерфейс не обещает изоляцию такого кода.

### Перехват с обязательным завершением

- Общий контракт допускает обработчик, который должен завершить исходную операцию одним решением. Модуль Interception интерпретирует это как пропуск, подавление или замену пакета.
- Контекст завершения принадлежит конкретному сеансу и исходной операции. Данные разрешено наблюдать и копировать; право завершения нельзя размножать рассылкой.
- Switch передаёт право решения выбранной ветке. Конфликтующие завершения, повторное завершение и просроченный ответ обнаруживаются исполнителем.
- Установить явные политики отсутствия обработчика, ошибки, тайм-аута, остановки и смены графа. Конкретные значения сроков определять измерениями, не зашивать необоснованную задержку.
- Внешние долгие действия запускаются после принятия решения по исходному перехвату. Сетевой ответ OBS не удерживает пакет клавиатуры.
- Учесть пары down/up, повторы, модификаторы, составные мышиные пакеты и одновременно активные переназначения. При отключении разрешать только принадлежащие механизму удержания.
- Срок ожидания результата не позволяет принудительно остановить произвольный C# внутри того же процесса. Поведение при зависшем обработчике и аварии исполнителя проверить отдельно, без обещания гарантированного восстановления ввода средствами одного таймера.

## Последовательность реализации

### Этап 1. Минимальный сквозной контракт

Изучить `NaSeqMen.Contracts`, `NaSeqMen.Runtime`, `NaSeqMen.Scripting` и текущие модули. Подготовить версию конфигурации для портов и связей. Реализовать небольшой синтетический модуль с событием, методом с несколькими аргументами, результатом и ошибкой.

Собрать маршрут «событие → C# с двумя выходами → вызов метода → Debug». Проверить типизированное и открытое сообщение, преобразование полей, Switch/Default и повторное использование одного подключения. Самоописание должно проходить от модуля через API до данных для редактора. На этом этапе не создавать большой каталог узлов.

Критерий завершения: новый тип узла подключается через опубликованный контракт без условий по имени модуля в ядре. Несовместимая связь отвергается с указанием портов. Метод получает согласованные аргументы одного вызова.

### Этап 2. C# и вложенные узлы

Расширить текущий `ScriptCompiler` и окружение. Поддержать именованные выходы, несколько сообщений, асинхронный вызов методов подключений и структурированные ошибки. Добавить определение портов и простой режим редактирования тела обработчика.

Составной узел публикует выбранные порты и параметры внутреннего графа. Ссылки на ресурсы передаются внутрь. Установить правила рекурсии, остановки и освобождения экземпляров. Проверить многократную перекомпиляцию, подписки и рост памяти; стратегия выгрузки требует отдельного технического решения.

Критерий завершения: ошибочная правка оставляет предыдущий обработчик, успешная применяется к новым сообщениям. Два экземпляра составного узла имеют независимую обработку и могут ссылаться на одно подключение. Разворачивание вложенности не меняет семантику графа.

### Этап 3. Редактор графа и диагностика

Заменить ограничения фиксированных слоёв отображением самоописанных блоков и портов. Сохранить плотность, темы, Tabler, EN/RU, масштаб, прокрутку и независимость WebView2/браузера. Использовать описания модулей для параметров, методов и свойств.

Добавить соединение совместимых портов, предложение преобразователей, несколько выходов, раскрытие составного узла и редактор C#. Категории и цвет служат навигации. Подписи и форма контактов сохраняют читаемость без одного только цвета.

Добавить Debug и временное наблюдение за портом/связью. Показывать сообщение, тип, источник, время, ветвь, результат/ошибку и переход к узлу. Буфер ограничен, потеря диагностических сообщений видна, пауза просмотра не останавливает обработку. Запись на диск оставлена открытым вопросом ниже.

Критерий завершения: пользователь собирает маршрут этапа 1 через обычный UI, сохраняет и повторно открывает его. Изменение данных и появление ошибок сохраняют геометрию. Рабочий граф продолжает исполняться при закрытом редакторе.

### Этап 4. OBS как проверка универсальности

Перенести существующий OBS-модуль на новый контракт. Использовать версионированное официальное описание протокола для каталога запросов, событий и типов. Сверять доступность запросов с подключённым сервером. Самоописание сервера не считать полным описанием схем полей.

Первый объём: запись, выбор сцены, чтение/установка громкости и уведомления о её изменении. Поддержать результат конкретного запроса, ошибки и подписки через общее подключение. Первоначальное чтение состояния выполняется явным запросом схемы.

Критерий завершения: одинаковые операции доступны визуальному вызову и C#. Изменение состояния непосредственно в OBS приходит как событие. Несколько одновременно ожидающих ответов сопоставляются верно. Недоступность OBS не останавливает посторонние графы.

### Этап 5. Полный адаптер Interception

Реализовать весь опубликованный API установленной библиотеки через собственную обёртку. Каталог включает жизненный цикл контекста, сведения и классификацию устройств, чтение/установку фильтров и precedence, ожидание с тайм-аутом, приём и отправку пакетов. Ожидание/чтение принадлежат одному обслуживающему циклу. Отдельные узлы не конкурируют за чтение одного сеанса.

Сохранить все поля и флаги клавиатурных/мышиных пакетов, включая колёса, движение и служебные признаки. Проверять количество отправленных пакетов. Подавление реализует обёртка без выдуманной нативной функции подтверждения. Отправка нового ввода доступна независимо от обработки перехваченного оригинала.

Связать обработчик пакета с общим контрактом обязательного завершения. Сначала проверить его на синтетическом транспорте, затем отдельно подтвердить на устройствах. Фильтры имеют определённого владельца; конфликтующие настройки обнаруживаются. Приоритет Interception не смешивать с приоритетом потока Windows.

Номер слота и Hardware ID не считать постоянной уникальной идентичностью экземпляра. Обнаружение одинаковых устройств, переподключение и неоднозначность должны иметь явно описанное поведение. При невозможности доказать нужное соответствие не выбирать произвольный экземпляр.

Критерий завершения: оригинал завершается однократно, остальные устройства следуют своим настройкам, подавление одной кнопки сохраняет остальные составляющие пакета, пары нажатий/отпусканий согласованы. Проверить ошибки, остановку, смену графа и частичную отправку. Действующий AHK и установленный драйвер принадлежат владельцу; согласование совместного физического перехвата требуется перед испытанием пересекающихся фильтров.

### Этап 6. Переход со старых конфигураций

Сохранить исходный файл и преобразовывать в новую версию только с отчётом. Перенести старые Source/Event/Condition/Transform/Script/Action в соответствующие новые узлы, сохранить match/miss, Default, enabled, локальные режимы Test и пользовательские имена. Старые C#-скрипты с `Input`/`Context` потребуют совместимого окружения либо явного отчёта о ручном переносе.

Разобрать различия смысла, которые нельзя перенести автоматически. Применять новую схему после проверки. Не считать сборку развёртыванием. Запуск новой версии в рабочем окружении выполнять отдельным этапом с сохранённой конфигурацией и возможностью возврата к `v0.0.1`.

## Сценарии приёмки

| Сценарий | Что проверяем |
|---|---|
| Выбранная кнопка → запись OBS | Независимые входной и выходной адаптеры; подавление завершается до сетевого вызова |
| Пульт → OBS → индикация на пульте | Команда и обратное событие, общее подключение, фактический статус |
| Переназначение клавиши/кнопки | down/up, повтор, модификаторы, другой интерфейс назначения |
| Два одинаковых устройства | Корректная привязка либо явная неоднозначность |
| Громкость → индикатор и управление обратно | Единицы, преобразование, внешний источник изменения, отсутствие эхо-петли |
| Один вход → несколько получателей | Явная рассылка и независимость данных ветвей |
| Switch с Default | Первое/все совпадения по настройке, однозначный маршрут завершения |
| Пользовательский метод с несколькими параметрами | Один согласованный вызов, результат и ошибка |
| Новый неизвестный ядру тип узла | Каталог, поля, порты и совместимость определяет описание |
| C# и составной узел | Именованные выходы, вложенность, правка без потери рабочей версии |
| Debug и закрытие редактора | Наблюдение не меняет поведение рабочего потока |

## Открытые решения и порядок уточнения

- Формат описания типов и JSON-представление открытых сообщений выбрать на этапе 1. Оценить удобство C#, диагностики, сериализации и копирования ветвей. Не делать обязательным `dynamic` для всего графа.
- Представление ресурса подключения на холсте и размещение вызовов уточнить на небольшом макете этапа 3. Семантика исполнения не зависит от раскладки.
- Политики состояния пользовательских узлов, перезагрузки скриптов и незавершённых операций описать до этапа 2. Не добавлять автоматически общее хранилище прошлых сообщений.
- Пользователь разрешил выборочное логирование и отладку. Для первой версии достаточно ограниченного живого просмотра. Дисковый журнал, срок хранения и replay требуют отдельного решения, если станут нужны.
- Конкретные политики тайм-аутов перехвата, удержания модификаторов и поведения при ошибке уточнить до физического испытания. Указать влияние на обычный ввод и измеренную задержку.
- Совместимость Interception с другими клиентами и точность идентификации устройств подтвердить испытанием. OpenInputBridge рассматривается позднее как ещё один адаптер/совместимый транспорт.

## Рабочие проверки для следующего исполнителя

Для этой машины `.NET CLI` потребовал `DOTNET_CLI_TELEMETRY_OPTOUT=1`, `DOTNET_CLI_USE_MSBUILD_SERVER=0`, `--disable-build-servers -m:1`. Временные каталоги тестов направлялись в `artifacts/checkpoint-temp` через `TEMP` и `TMP`.

Использованные команды:

```powershell
dotnet build NaSeqMen.slnx -c Release --nologo --no-restore --disable-build-servers -m:1
dotnet tests/NaSeqMen.RuntimeChecks/bin/Release/net11.0-windows/NaSeqMen.RuntimeChecks.dll
# В tests/NaSeqMen.WebChecks, со своим свободным локальным тестовым портом:
# NASEQMEN_TEST_URL=http://127.0.0.1:PORT
node checks.mjs
```

Браузерные проверки должны использовать актуальный wwwroot и подменённые API. Файлы в local/ и artifacts/ исключены из Git. В текущем окружении сетевой sandbox блокировал доступ Chrome к тестовому серверу; успешный прогон выполнен после разрешённого запуска обоих вне этой сетевой изоляции.
