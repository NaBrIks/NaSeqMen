## Реализованный срез альфы

Точный контракт находится в [alpha-contract.md](alpha-contract.md). По прямому выбору владельца исполнитель — отдельный .NET 11 процесс с треем, HTTP API и живым WebSocket на loopback. Новый HTML-редактор обслуживается отдельным ASP.NET Core 11 процессом; прежний WPF-редактор сохранён рядом. Модули загружаются исполнителем из DLL, C# компилируется Roslyn 4.14 при применении конфигурации. Доступны источники, условия, преобразования, сценарии, действия и ацикличные связи. По умолчанию включён пробный прогон.

Альфа выполняет **доверенный локальный C#**, не создаёт sandbox и не обещает подавления прямых обращений к Windows/сети/файлам. Пробный режим подавляет действия узлов и `Context.EmitAsync`; произвольный внешний вызов из сценария вне этой гарантии. Бесконечный цикл пользовательского кода может остановить обработку последующих событий; отмена кооперативная. Такие сценарии в проверках не запускались.

Временная очередь текущей обработки ограничена 2048 сообщениями, буфер каждого живого клиента диагностики — 512. Они не доступны как хранилище/история и не восстанавливаются. На переполненный синтетический ввод API отвечает 429; пассивный аппаратный источник сообщает диагностическую потерю. Устаревший подписчик получает признак пропущенной диагностики при возобновлении доставки. После подключения истории нет. Число переходов одного события ограничено 4096.

В следующих разделах описаны целевые границы и предложения развития. В частности, гарантия завершения физической пары Down/Up при любой смене правил должна проверяться вместе с конкретным выходным модулем; один ацикличный граф сам по себе её не доказывает.

## 1. Граница процессов

Приложения: `NaSeqMen.Executor.exe`, сохранённый `NaSeqMen.Editor.exe` и новый `NaSeqMen.Editor.Web.exe`. Последний раздаёт HTML/CSS/JavaScript в браузер и передаёт разрешённые HTTP/WS-запросы исполнителю, а не выполняет пользовательские цепочки.

Исполнитель работает в пользовательском сеансе независимо от редактора; значок в трее даёт доступ к управлению его работой. Он загружает конфигурацию и модули, владеет соединениями, принимает ввод, выполняет цепочки и отправляет живую диагностику подписанному редактору. Установка системной службы не требуется исходной моделью.

Редактор подключается к исполнителю через отдельный API. Он получает конфигурацию и описания возможностей модулей, редактирует схему и показывает текущий поток диагностики. Закрытие, переподключение или медленная работа редактора не должны менять обработку физического ввода.

Для HTML браузер обращается к `http://127.0.0.1:17964`; локальный веб-сервер связывается с исполнителем на `http://127.0.0.1:17963`. API-token из `local/api-token.txt` добавляется только сервером. Рабочий C# остаётся на стороне исполнителя, JavaScript отвечает только за интерфейс. Веб-процесс не содержит второго экземпляра runtime и не сохраняет отдельную копию конфигурации. Подробности границы — в [web-editor.md](web-editor.md).

Через редактор не проходят события между устройством и действием. Исполнитель также не обращается в редактор за решением условия или выполнением C#.

API управления отделён от протоколов модулей: подключение редактора к исполнителю и подключение модуля к OBS — разные соединения с разными владельцами и назначением.

## 2. Что коммутируется

| Понятие | Смысл |
|---|---|
| Событие | Конкретное поступление: нажатие, отпускание, внешнее сообщение |
| Значение | Данные данного поступления: число, текст, логическое значение, структурированный набор полей |
| Условие | Проверка, пропускающая или останавливающая данную ветвь |
| Преобразование | Получение выходных данных из входных данных данного вызова |
| Действие | Обращение к выходному модулю с конкретными аргументами |
| Результат вызова | Завершение либо ошибка конкретного действия, если модуль умеет это сообщать |

Нет отдельной сущности «состояние приложения», каталога последних значений, retained-сообщений, replay или восстановления после подключения. Новое подключение редактора не получает прошлые события. Внешнее сообщение о громкости — обычное входное сообщение, которое можно направить на ползунок, без сохранения громкости внутри ядра.

Конфигурация сохраняется: соединения, параметры модулей, сопоставления устройств, схема, исходники сценариев и настройки редактора. Это не сохранение обрабатываемых данных.

## 3. Предлагаемый внутренний маршрут

Источник → условие, если оно задано → преобразование/сценарий, если задано → действие или выходной контакт.

Это логический маршрут. Промежуточные этапы необязательны; цепочка может ветвиться. При обратном сообщении OBS выступает источником, а панель — получателем. Никакого особого «обратного исполнителя» не требуется.

Каждое поступление получает техническую привязку к источнику, порядку поступления и выполняемой версии конфигурации. Метка прохождения позволяет редактору сопоставлять ветви одного запуска; пользовательские названия остаются основным представлением в UI.

Предложение для первого этапа: внутри одной входной последовательности сохранять порядок; параллельность независимых источников не должна создавать обещания единого физического порядка. Порядок нескольких действий задаётся последовательностью/макросом, а не расположением проводов. Неявное объединение нескольких ветвей с ожиданием всех входов не вводить.

Предложение для первой версии схем: не разрешать замкнутый путь проводов. Обратная связь через внешнюю программу — отдельное входное событие; защита от её повторной генерации относится к контракту конкретной интеграции и правилам, а не к сравнению с сохранённым последним значением.

## 4. Модуль и соединение

Модуль — отдельный подпроект и поставляемый пакет. Он предоставляет описание возможностей и их реализацию, но не диктует ядру устройство своего внешнего протокола.

| Часть контракта | Содержание |
|---|---|
| Описание пакета | Имя, версия, совместимость с контрактом исполнителя, необходимые зависимости |
| Настройки | Описание параметров для стандартных полей редактора |
| Возможности | Входы, условия, преобразования, действия и типы их данных |
| Соединения | Создание и закрытие конкретного именованного подключения |
| Выполнение | Приём входного сообщения, вызов операции, завершение или ошибка |
| Диагностика | Сообщения о прохождении и технических ошибках текущей работы |

Один экземпляр соединения, например «OBS рабочий», обслуживает все ссылающиеся на него входы и действия. Добавление кнопки в схему не открывает новый сокет. Модуль ввода аналогично владеет доступом к выбранному устройству и его интерфейсам.

Условие «программа сейчас активна» запрашивает внешний контекст при обработке события через соответствующий модуль. Результат относится к этой проверке, не записывается в каталог состояний. Наблюдение за сменой активной программы, если модуль его предоставляет, является отдельным источником событий.

При разрыве внешнего подключения модуль сообщает об отказе соответствующего действия. Автоматически повторять команды после восстановления нельзя: это может повторно запустить действие. Переподключение транспорта не означает повтор сообщений или синхронизацию значений.

Загрузка пакетов в процесс и отдельный процесс модуля — технические варианты, а не утверждённый выбор. В первой реализации важнее отделить контракт от реализации, чем вводить универсальный удалённый хост модулей.

## 5. C# как пользовательское расширение

Простые назначения создаются выбором готовых действий. Пользовательский C# подключается как обработчик в схеме и получает окружение исполнителя. Не нужен отдельный язык макросов.

Предлагаемый состав окружения:

- входное событие и его данные;
- настроенные параметры обработчика;
- выдача данных на объявленный выходной контакт;
- обращение к действиям и проверкам модулей через общий контракт;
- диагностический вывод, связанный с текущим запуском;
- отмена текущего запуска и ожидание в последовательности действий.

Сценарий должен объявлять контакты и ожидаемые типы, чтобы редактор проверял связи так же, как для готового блока. Необязательно отображать программный текст на самой схеме: достаточно компактного блока с именем и отдельного редактора кода.

Предложение по циклу работы: редактирование → проверка и компиляция при применении → выполнение подготовленного обработчика на событиях. Ошибка компиляции не заменяет работающую конфигурацию. Компиляция на каждое нажатие не нужна.

Roslyn Scripting позволяет выполнять C# с переданными объектами окружения и заранее готовить повторно вызываемый обработчик. Это кандидат реализации, а не выбор версии платформы или готовый установленный компонент. Основание: [официальные примеры Roslyn Scripting](https://github.com/dotnet/roslyn/blob/main/docs/wiki/Scripting-API-Samples.md).

Макрос — упорядоченные действия одного сценария: выполнить, при необходимости дождаться завершения, выдержать явно заданную задержку, продолжить либо отменить. Параллельные ветви не превращаются автоматически в макрос.

Пользовательский сценарий не получает от ядра хранилище переменных между вызовами, последние входные значения или восстановление запуска. Возможность написать произвольный C# сама по себе не вводит эти возможности в архитектуру коммутатора.

## 6. Пробный прогон

Пробный прогон использует тот же маршрут условий и преобразований, но подавляет внешние действия на границе выполнения. Он сообщает: «сформирована такая команда с такими аргументами; отправка подавлена».

Прогон не утверждает, что приложение выполнит команду, не подменяет ответ успехом и не моделирует результат внешней программы. Если продолжению нужен результат подавленного действия, ветвь останавливается с явным объяснением. Система тестовых ответов не входит в исходный объём.

Вызовы из C# должны проходить через предоставленное окружение, если требуется этот режим. Прямой вызов операционной системы, файлов или сети из произвольного C# находится вне такой гарантии. Обычная загрузка кода в отдельную сборку не является обещанием изоляции его побочных эффектов.

В альфе сценарии являются доверенным локальным кодом. Редактор обязан явно показывать ограничение пробного прогона действиями окружения. Более строгая изоляция остаётся отдельным будущим решением; не выдавать текущий режим за sandbox произвольного C#.

Подавление выходного действия и подавление исходного физического ввода — разные настройки. При изучении мыши необходимо явно выбрать наблюдение либо перехват. Нельзя обещать, что исходная кнопка не повлияет на Windows, если модуль лишь наблюдает за ней.

Режим выполнения выбирается для запуска целиком. Нельзя отправить реальное нажатие, переключить оставшуюся часть того же взаимодействия в пробный режим и подавить обязательное отпускание.

## 7. Нажатие, отпускание и смена конфигурации

Вход сохраняет различие нажатия и отпускания; выход предлагает отдельные операции зажатия, отпускания и полного нажатия. Это необходимо для поведения, где первая часть комбинации выполняется при нажатии физической кнопки, а вторая — при отпускании.

Завершение уже начатого воздействия — обязанность выходного модуля и текущего выполнения. Если контекст активного окна изменился, это не должно запрещать отпускание клавиши, которую модуль уже зажал.

Отмена и ошибка сценария завершают принадлежащие ему воздействия: нельзя отпускать все клавиши пользователя глобально или приписывать себе чужие нажатия. Это требование к ресурсу текущей операции, не сущность состояния коммутатора.

При смене схемы нельзя отправлять Down по прежнему назначению, а Up по новому. Предложение: активные взаимодействия завершаются по прежнему назначению либо явно отменяются с корректным завершением; только после этого новое назначение применяется к следующим взаимодействиям. Подробный механизм решается при проектировании входного/выходного модуля.

Медленный сценарий не должен задерживать физический ввод в ожидании редактора, сети или компилятора. Отдельно следует определить политику допустимого времени проверки при перехвате и предсказуемое поведение при её превышении. Не выбирать молча «пропускать всё» для устройства, которому владелец назначил блокирование.

При перегрузке нельзя без разбора отбрасывать события: потеря отпускания и пропуск одного показания ползунка имеют разные последствия. Политика допустимого объединения значений объявляется конкретным входом; клавишные пары не объединяются как числовой поток.

## 8. API редактора и применение конфигурации

Минимальные группы операций:

| Группа | Назначение |
|---|---|
| Возможности | Согласовать версию API, получить описания модулей и типов |
| Конфигурация | Прочитать, проверить и применить соединения, сопоставления, схему и сценарии |
| Управление | Запустить/остановить выбранное выполнение, выбрать пробный режим |
| Диагностика | Подписаться на живое прохождение и ошибки, прекратить подписку |
| Изучение устройства | Начать/закончить наблюдение или разрешённый захват, передать результаты в UI |

Сохранение конфигурации и её применение согласуются исполнителем. Предложение: редактор передаёт исходную ревизию; при конфликте изменения не затираются молча. Подготовленная версия проверяется целиком до её применения. Это ревизия конфигурации, не история событий и не восстановление состояния.

Для альфы выбран HTTP API с WebSocket-потоком диагностики на 127.0.0.1:17963 и локальным token. Контракт сообщений отделён от выбора транспорта. Удалённый доступ не является исходным требованием.

## 9. Живая диагностика

Исполнитель выдаёт наблюдения на этапах: вход получен, условие пропустило/отклонило, преобразование завершилось, выход сформирован, отправка подавлена/выполнена, операция завершилась/ошиблась.

Наблюдение содержит связь с текущим запуском, элементом схемы и конкретными входными/выходными данными. Редактор подсвечивает контакты и связи, показывает причину остановки и последовательность событий. Это не глобальный журнал для последующего проигрывания.

Поток диагностики не должен блокировать выполнение. Его транспортные буферы ограничены; при пропуске диагностических сообщений редактор получает явный признак потери. Потеря наблюдений не означает, что сами действия не выполнялись.

Отображение — ограниченный текущим сеансом просмотра список в редакторе, без записи на диск, без восстановления и без API получения прошлых значений. В HTML-редакторе новые строки прокручивают журнал только при просмотре его конца; при чтении выше позиция сохраняется. Самостоятельный архив диагностики не добавляется. Панель обнаруженных кнопок также относится только к текущему просмотру и не участвует в исполнении схемы.

## 10. Проверяемые границы первой реализации

- Исполнитель продолжает обработку при закрытом редакторе и при обрыве его канала.
- Подключившийся редактор видит конфигурацию и новые события, но не получает прошлые значения.
- Две цепочки используют один экземпляр внешнего соединения в обоих направлениях.
- Пробный прогон выдаёт описание намерения, но не отправляет действие и не сообщает ложный успех.
- Down/Up проходят в порядке, отмена и смена схемы не оставляют принадлежащую сценарию клавишу зажатой.
- Ошибка компиляции не заменяет действующую схему; одинаковые проверки типов действуют для готовых блоков и C#.
- Медленный диагностический клиент не тормозит ввод; потери его наблюдений обозначаются явно.
- Не появляются API последних значений, восстановление сценариев, replay или автоматический запрос внешнего состояния при подключении.

Для текущей альфы по выбору владельца используется .NET 11; установлен SDK 11.0.100 и runtime 11.0.0. Roslyn 4.14, localhost HTTP/WebSocket и загрузка модульных DLL в процесс сохраняются. Развитие изоляции произвольного C# остаётся открытым техническим решением. Установка драйвера перехвата и вмешательство в действующий AHK не входят в реализацию альфы.
