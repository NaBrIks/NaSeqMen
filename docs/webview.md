# Окно NaSeqMen на WebView2

Основной запуск `Start-NaSeqMen.cmd` открывает `NaSeqMen.Desktop.exe`: обычное изменяемое окно Windows с HTML-редактором внутри WebView2. У окна нет адресной строки или панелей внешнего браузера. Нативный контейнер написан на C# / WinForms, цель — `net11.0-windows`. Все рабочие страницы, схема и формы остаются в единственном `src/NaSeqMen.Editor.Web/wwwroot`; отдельной нативной реализации этих экранов нет.

Браузерный вариант сохраняется в `Start-NaSeqMen-Web.cmd`, прежний WPF — в `Start-NaSeqMen-Wpf.cmd`. Общий исполнитель не меняется и работает независимо от открытых редакторов.

Исполнитель создаёт значок [Tabler arrows-split](https://github.com/tabler/tabler-icons/blob/main/icons/outline/arrows-split.svg) в трее. Один левый клик или пункт «Открыть редактор» открывает окно WebView2. Если окно уже работает в этой копии проекта и сеансе Windows, исполнитель выводит его на передний план и восстанавливает из свёрнутого состояния.

После загрузки HTML шапка WebView2 служит заголовком окна, а кнопки сворачивания, разворачивания и закрытия размещены справа в той же строке. Перед загрузкой и при ошибке доступен стандартный заголовок.

## Запуск и владение

`scripts/start-desktop.ps1` собирает приложение при отсутствии опубликованного EXE и открывает видимое окно. `-Rebuild` пересобирает его после закрытия окна. Скрипт сохранён UTF-8 с BOM для Windows PowerShell. `scripts/build.ps1` собирает все варианты; результат desktop — `artifacts/alpha/desktop`.

Окно проверяет `http://127.0.0.1:17963/api/health` и имя исполнителя. Если на этом порту нет слушателя, запускает `artifacts/alpha/executor/NaSeqMen.Executor.exe --root <проект>` без консоли и ждёт готовности. Неизвестный или неотвечающий слушатель не подменяется. Исполнитель создаёт API-token сам. Закрытие окна никогда не останавливает исполнитель.

Далее проверяется `http://127.0.0.1:17964/web-health`. Уже запущенный сервер с правильным именем и адресом исполнителя используется без присвоения владения. Если сервера нет, окно создаёт тот же `WebEditorHost.Build(...)`, который использует отдельный браузерный EXE, и запускает его внутри процесса. При закрытии останавливается только принадлежащий этому окну host. Закрытие окна, использующего чужой host, оставляет сервер работающим. Если другое окно пользовалось host первого окна, после его закрытия оно теряет подключение; автоматическая передача владения не реализована.

`WebEditorHost.Build(root, port, executorPort)` возвращает `WebApplication`; запуск и завершение принадлежат вызывающему приложению. В отдельном веб-EXE `Program.cs` остаётся разбор аргументов и `RunAsync`. HTML-прокси, whitelist API, проверка Origin/Host и передача диагностики общие для обоих способов открытия.

Профиль WebView2 хранится в игнорируемом `local/webview2`. Это browser storage, настройки вида и кеш, не хранилище состояний исполнителя. Файлы интерфейса включаются в публикацию desktop через MSBuild Link, без второй копии исходников.

## Навигация и ошибки

Внутри окна разрешён только origin `http://127.0.0.1:17964`. Обычная внешняя HTTP/HTTPS-ссылка, открытая пользователем, передаётся браузеру по умолчанию. Скриптовые внешние переходы, перенаправления во внешний браузер, опасные схемы и URI с credentials не запускаются. Всплывающие окна обрабатываются теми же правилами. Для объединённого заголовка Desktop принимает с origin редактора только сообщение с тремя RGB-цветами активной темы TechnicalShell. Desktop рисует кнопки окна и обрабатывает их нажатия. Native host objects выключены. API-token остаётся внутри общего серверного host.

При закрытии Desktop сохраняет обычные границы окна и признак развёрнутого состояния в `local/window-placement.json`. При старте после смены монитора окно возвращается в доступную рабочую область.

Ошибка начального подключения или отсутствующий WebView2 Runtime показывается в существующем компактном месте запуска с «Повторить» и «Подробности». Подробности открываются только кнопкой. Драйверы, автозапуск и браузерные среды автоматически не устанавливаются.

## Зависимость и проверка

Официальный пакет Microsoft.Web.WebView2 версии **1.0.4314.35** выбран по стабильной версии [NuGet](https://www.nuget.org/packages/Microsoft.Web.WebView2/1.0.4314.35). Использованы стандартные API [WinForms WebView2](https://learn.microsoft.com/en-us/microsoft-edge/webview2/gettingstarted/winforms) и правила [пользовательских popup-запросов](https://learn.microsoft.com/en-us/dotnet/api/microsoft.web.webview2.core.corewebview2newwindowrequestedeventargs.isuserinitiated). Для запуска требуется установленный Microsoft Edge WebView2 Runtime. Его installer в альфу не включён; SDK-пакет не заменяет Runtime. Уведомления LICENSE и NOTICE пакета копируются в `licenses/WebView2` при публикации. Неиспользуемая WPF-обёртка пакета исключена из references; приложение использует WinForms wrapper.

Проверки без запуска окна: `dotnet run --project tests/NaSeqMen.DesktopChecks -c Release`. Подтверждены 23 проверки ограничений навигации, создания собственного host на тестовом 17966, повторного использования, завершения только своего host и продолжения работы настоящего исполнителя. Исполнитель должен уже работать; проверка не запускает его и не изменяет конфигурацию. Общий backend после выделения `WebEditorHost` повторно прошёл 28 проверок `scripts/check-web-backend.py`.

Сборка и публикация desktop проходят без предупреждений и ошибок. Интегратор запустил настоящий `Start-NaSeqMen.cmd`: окно WebView2 открылось, получило конфигурацию и живой поток, показало TechnicalShell и таблицу устройств. Конфигурация исполнителя не изменилась. Браузерные снимки и 43 сценария проверены отдельно; это не полная ручная приёмка всех действий пользователем.
