# Проверка первой альфы

Дата: 2026-11-15. Версия: 0.1.0-alpha. Работа локальная, коммитов и публикации нет. Все проверки ниже относятся к этому срезу, не к полной готовности продукта.

## Подтверждённые результаты

### Формы ролей, связи и назначения мыши

В WebView2 роль выбирается перед открытием формы. У сохранённого узла она закреплена также при валидации и применении через API. В формах конечные варианты показаны радиокнопками. 48 браузерных проверок включают отдельный редактор роли и удаление выделенной кривой связи без удаления узлов; 19 проверок раскладки включают разделение проводов у общего выхода.

В локальной схеме две боковые кнопки настроены на Ctrl+C и Ctrl+V, а нажатие D с клавиатурного интерфейса мыши — на Ctrl+X. Выход выполняется один раз при нажатии, автоповтор отбрасывается. Тест настоящего модуля действия с подменой системной клавиатуры подтвердил порядок down/up, фильтр источника и подавление по режиму схемы, источника и действия.

При физическом нажатии кнопки вырезания в рабочем режиме обнаружены Win down, D up и Win up. Действие Ctrl+X не запустилось. Windows обработала Win+D и показала рабочий стол. Raw Input наблюдает доступные события без блокировки исходной комбинации. KOE привязывает D к вырезанию через перехватчик с включённой блокировкой исходного клавиатурного ввода.

Проверка установленного Interception на целевом ПК нашла оба интерфейса мыши, но фильтр остался нулевым после установки. Системное подавление на этой машине не подтверждено. Вкладка обнаружения может изолировать события от схемы NaSeqMen независимо от доступности драйвера.

Статические файлы Desktop/Web совпадают с исходниками. ## Что проверено поведением

- Probe-модуль физически не вызывается в dryrun, в том числе из Context.EmitAsync пользовательского C#. В live проверке вызывается только тестовый модуль, пишущий маркер в собственный local test directory.
- Условие останавливает ветку; числовое преобразование и реальный Roslyn C# меняют сообщение. Неверный C# и цикл отвергаются до применения, рабочая конфигурация остаётся.
- Результат C# различает Suppressed и реальное завершение. Пробный режим не выдаёт фиктивного внешнего успеха.
- Известная несовместимость контактов отвергается; any не сужается автоматически. Несовпадение фактического типа останавливает ветку до действия.
- Диагностика routed содержит оба узла конкретного перехода. У заблокированного условия нет исходящего перехода. Пропуск переполненного живого диагностического канала обозначается даже после окончания всплеска.
- Новый подписчик не получает replay. Исполнитель работает без редактора и диагностического клиента. Наблюдаемые значения не сохраняются.
- API требует token, чужой Origin отвергается; инъекция не может представиться аппаратным модулем. Синтетический вход имеет Module=test и Source=synthetic.
- Сопоставление меняет имя сообщения для графа, но исходное событие остаётся видимым в режиме изучения. Неподдерживаемая политика подавления явно отвергается.
- Недоступное соединение не мешает запуску исполнителя с валидной конфигурацией; повторное сохранение повторяет попытку. Ошибка explicit Apply сохраняет прежнюю конфигурацию.
- Клавиатурный модуль проверен без реального SendInput: парные down/up, shared modifiers, повторные нажатия, отмена, ошибочная отправка и cleanup собственных удержаний. Это не аппаратная проверка.
- OBS mock проверяет авторизацию, запросы, ответы, события, параллельную корреляцию и отсутствие начального снимка. Реальный граф выполняет GetVersion, GetSceneList и GetRecordStatus; ответ приходит через то же именованное соединение в другую ветку. Запись остаётся выключенной.

## Ошибка C# после обновления установленного .NET (2026-11-15)

Повторная проверка текущей конфигурации через `POST /api/config/validate` воспроизвела ошибки CS0012 для `Object` и `IsExternalInit` со ссылкой на `System.Runtime, Version=10.0.0.0`. Причина установлена по загруженным модулям: старый процесс исполнителя продолжал работать на .NET 10.0.14, но `System.Runtime.dll` из его каталога уже отсутствовал после обновления среды до 10.0.15. Загруженный код продолжал выполняться, однако Roslyn при новой компиляции не мог прочитать метаданные удалённой сборки.

Новый процесс `dotnet run --project tests/NaSeqMen.RuntimeChecks -c Release`, собранный SDK 11.0.100 для прежней цели `net10.0-windows`, прошёл все 21 проверки. В том числе выполнены реальная компиляция C#, `await Context.EmitAsync(...)`, изменение record через `with`, обработка ошибок компиляции и сохранение предыдущей рабочей конфигурации. Изменять исходники сценария или добавлять случайные ссылки на сборки не требуется. Для запущенного экземпляра требуется штатный перезапуск исполнителя: меню значка в трее → «Завершить исполнитель», затем обычный запуск и повторная проверка схемы. Конфигурацию, драйверы, AHK и OBS менять не нужно.

В рабочей сессии интегратор перезапустил исполнитель с сохранением конфигурации и включённым пробным режимом. Меню трея оказалось недоступно через автоматизацию, поэтому прежний процесс завершён адресно, не штатным пунктом меню. После запуска нового процесса проверка той же схемы вернула `valid: true`, `errors: []`.

## Ограничения первой альфы

1. Raw Input только наблюдает. Адресное подавление, политика полного блокирования физической мыши и полная замена KOE ещё не реализованы. Текущий AHK/Interception может изменить события до наблюдения; он не выключался.
2. Интерфейсы составного устройства пока показываются отдельно. Автоматическая физическая группировка, восстановление идентичности после переподключения и реальная раскладка всех кнопок владельца требуют дальнейшей проверки.
3. Модуль NaSDock/USB, прошивка и физическая панель не включены в настольную альфу. Соседний NaSDock не менялся.
4. C# и DLL-модули доверенные, исполняются в процессе. Прямой I/O произвольного C# обходит host dryrun; бесконечный пользовательский цикл может задержать исполнитель. Изоляция процесса не реализована.
5. OBS не переподключается автоматически после обрыва: повторное сохранение соединения повторяет Connect. Повтор внешних действий и получение снимков не выполняются.
6. В альфе одно активное описание графа, минимальный API модулей и несколько типов значений. Это не готовый marketplace или стабильный публичный SDK.
7. Реальное SendInput с активной программой, одновременное физическое/синтетическое удержание и вся аппаратная мышь не испытывались. Для этого нужна отдельная контролируемая проверка, а не вмешательство в работающий KOE.
