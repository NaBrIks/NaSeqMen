# Фоновый ввод текста

## Назначение

Узел **Фоновый ввод текста** отправляет строковую полезную нагрузку входящего сообщения напрямую в целевое окно Windows в фоновом режиме через Win32 `PostMessageW(WM_CHAR)` без переключения фокуса. Узел умеет автоматически находить классические текстовые поля Win32 (или указанный класс дочернего окна) и работает как самостоятельно, так и в связке с узлом **Фокус на окно**.

## Типичные сценарии

- **Фоновая запись в Блокнот или редактор на Scintilla:** укажите *Процесс* `notepad` (или `notepad++`) и подайте на вход отформатированный текст из **C#-функции** или **ВЕРХНИЙ РЕГИСТР (CAPS)**, чтобы тихо дописывать заметки, не отвлекаясь от активного окна.
- **Связка с «Фокус на окно» без переключения фокуса:** поставьте перед этим узлом **Фокус на окно** со снятым флажком *Вывести вперёд* (`focus = false`), а в **Фоновом вводе текста** оставьте поля *Процесс* и *Заголовок* пустыми — будет использован `properties["targetHwnd"]` из корзины.
- **Отправка в конкретное поле классического диалога:** задайте *Класс дочернего окна* (определённый, например, через Spy++), чтобы посылать символы именно в нужное поле ввода внутри Win32-окна.

## Порты

### Входы

- **`in` (Текст, `String`)** — сообщение, текст которого посимвольно отправляется через `WM_CHAR` (символы `\r` пропускаются). Пустые строки игнорируются.

### Выходы

- **`sent` (Отправлено, `String`)** — копия сообщения после успешной отправки со свойством `properties["postedHwnd"]` (дескриптор окна в шестнадцатеричном виде, например `"0x1A0F2"`).
- **`notFound` (Не найдено, `String`)** — копия сообщения, если целевое окно не найдено или отправка не удалась.

## Настройка и советы

- **Активен (отправка) (`active`, по умолчанию: `true`):** снимите флажок для временного отключения фоновой отправки (статус `muted`) без разрыва связей.
- **Процесс (`processName`, по умолчанию: пусто) и Заголовок (`titleContains`, по умолчанию: пусто):**
  - Если заполнено хотя бы одно поле, узел сам ищет подходящее видимое окно.
  - Если **оба** поля пусты, автоматически используется `properties["targetHwnd"]`, записанный узлом **Фокус на окно**.
- **Класс дочернего окна (`childClass`, по умолчанию: пусто):** необязательное имя класса дочернего Win32-элемента (точное или подстрока без учёта регистра). При пустом значении выполняется автопоиск стандартных полей (`RichEditD2DPT`, `Edit`, `Scintilla`, `RichEdit20W`, `RICHEDIT50W`), а если они не найдены — отправка идёт в само окно верхнего уровня.
- **Совместимость приложений:** фоновый `WM_CHAR` хорошо работает с классическими Win32-контролами (Блокнот, Notepad++/Scintilla, классические утилиты), но современные приложения на Electron/Chromium, UWP и игры на DirectX обычно игнорируют `WM_CHAR` без фокуса. Для них используйте связку **Фокус на окно** (с включённым *Вывести вперёд*) -> **Ввод текста (клавиатура)**.
- **Окна с правами администратора (UAC):** механизм Windows UIPI блокирует `PostMessage` от обычного процесса к окну с повышенными правами.
