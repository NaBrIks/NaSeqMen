# C#-функция

## Назначение

Узел **C#-функция** один раз компилирует фрагмент кода C# при запуске потока через Roslyn и выполняет его для каждого сообщения, поступающего на вход `in`. Он даёт полную гибкость .NET для фильтрации, счётчиков и состояний между сообщениями, форматирования данных, управления действиями перехвата (`Suppress`, `SendKeys`, `SendMouse`) и формирования сложных запросов (например, для **OBS Studio**).

## Типичные сценарии

- **Счётчики, переключатели и подавление дребезга:** хранение промежуточных данных в словаре `state` для подсчёта нажатий, ограничения частоты событий или чередования режимов без лишних узлов.
- **Пользовательская логика перехвата ввода:** проверка свойств в `props`, вызов `Suppress(true)` для блокировки исходного события и `SendKeys("LCtrl+C")` или `SendMouse(...)` для условного переназначения.
- **Условная фильтрация и преобразование:** анализ `text`, `topic` или `props`, отбрасывание ненужных сообщений через `Drop()` и модификация полезной нагрузки для остальных.
- **Формирование произвольных команд OBS WebSocket:** возврат словаря `Dictionary<string, object?>` с полями `requestType` и `requestData` для порта `command` узла **OBS Studio**.

## Порты

### Входы

- **`in` (Вход, `Any`)** — входящая корзина сообщения. В скрипт передаётся её рабочая копия `msg`.

### Выходы

- **`out` (Выход, `Any`)** — результирующее сообщение, если не была вызвана функция `Drop()` и не возникла ошибка.
- **`error` (Ошибка, `String`)** — сообщение об ошибке компиляции (`properties["errorKind"] = "compile"`) или исключении во время выполнения (`properties["errorKind"] = "runtime"`, плюс `exceptionType` и `stackTrace`). Ошибки также дублируются в панель отладки.

## API скрипта (`ScriptGlobals`)

Скрипт получает готовые глобальные объекты и подключённые пространства имён (`System`, `System.Linq`, `System.Collections.Generic`, `System.Text`, `System.Text.Json`, `System.Text.RegularExpressions`, `NaSeqMen.Core.Messages`):

| Элемент | Тип / Сигнатура | Описание |
| :--- | :--- | :--- |
| `msg` | `FlowMessage` | Клонированная рабочая копия входящего сообщения. |
| `payload` | `object?` (чтение/запись) | Сокращение для `msg.Payload`. |
| `text` | `string` (чтение) | Сокращение для `msg.PayloadAsString()`. |
| `topic` | `string?` (чтение/запись) | Сокращение для `msg.Topic`. |
| `props` | `Dictionary<string, object?>` | Сокращение для `msg.Properties`. |
| `state` | `Dictionary<string, object?>` | Словарь состояния узла, сохраняемый между сообщениями до остановки/перезапуска потока. |
| `suppress` | `bool?` (чтение/запись) | Чтение/запись `msg.Properties["suppress"]` (`null` удаляет ключ). |
| `Suppress(bool value = true)` | `void` | Устанавливает `msg.Properties["suppress"] = value` (для цепочек Interception). |
| `SendKeys(string sequence)` | `void` | Устанавливает `msg.Properties["sendKeys"] = sequence` (например, `"LCtrl+X"`). |
| `SendMouse(string action)` | `void` | Устанавливает `msg.Properties["sendMouse"] = action`. |
| `Drop()` | `void` | Отменяет отправку сообщения на выход `out`. |
| `Log(string message)` | `void` | Публикует строку в панель отладки с меткой `"script"`. |
| `Clone(object? newPayload = null)` | `FlowMessage` | Создаёт копию `msg`, при желании заменяя полезную нагрузку. |

### Правила возвращаемого значения

- `return msg;` (или другой объект `FlowMessage`) — на `out` отправляется возвращённый `FlowMessage`.
- `return value;` (любое не-`null` значение, не являющееся `FlowMessage`) — отправляется `msg` с новым `Payload = value`, а `topic` и `props` сохраняются.
- Без `return` (или `return null;`) — отправляется изменённый рабочий объект `msg`.
- `Drop(); return null;` — на `out` ничего не отправляется.

## Настройка и советы

- **C#-скрипт (`code`):** компилируется один раз при старте потока, поэтому обработка отдельных сообщений выполняется быстро и без накладных расходов на компиляцию.
- **Потокобезопасность `state`:** вызовы внутри одного узла **C#-функция** выполняются последовательно, поэтому дополнительная синхронизация при работе со `state` не требуется.
- **Сброс при перезапуске:** словарь `state` очищается при каждой остановке и повторном запуске потока.
- **Пример — пороговый фильтр со счётчиком:**
  ```csharp
  if (!double.TryParse(text, out var level) || level < 70)
  {
      Drop();
      return null;
  }

  var hits = state.TryGetValue("hits", out var v) ? (int)v! : 0;
  state["hits"] = ++hits;
  Log($"Превышение #{hits}: {level}");
  return $"PEAK {level:0.0}%";
  ```
- **Совет по отладке:** на этапе разработки подключите порт `error` к узлу **Отладка**, чтобы сразу видеть ошибки компиляции и трассировку исключений.
