# Устройство Interception

## Назначение

**Устройство Interception** перехватывает аппаратные события **одной** физической клавиатуры или мыши через драйвер ядра Interception, выдаёт их на выход **`Событие ввода`** и принимает обратные решения или прямую отправку на вход **`Возврат / Действие`**.

### Когда выбирать Устройство, а когда — Хаб Interception
- Выбирайте **Устройство Interception**, если схеме нужно одно конкретное устройство (например, один дополнительный кейпад или одна мышь), требуются индивидуальные **`Действие по умолчанию`** / **`Таймаут решения (мс)`** или нужен встроенный ручной тест через **`Тестовая клавиша`**.
- Выбирайте **Хаб Interception**, если вы координируете несколько клавиатур и мышей в одной схеме или хотите использовать порт **`Все события`** для поиска устройств.

## Типичные сценарии

- **Отдельный дополнительный кейпад:** Привяжите USB-кейпад по его `Hardware ID`, соедините **`Событие ввода`** с **Коммутатором хоткеев**, а **`Возврат`** — с **`Возврат / Действие`**, оставив основную клавиатуру полностью вне перехвата.
- **Переназначение кнопок конкретной мыши:** Выберите **`Тип устройства` = `Мышь`**, укажите мышь в списке **Connected Devices**, оставьте **`Захват движения мыши`** выключенным и переназначьте боковые кнопки (`X1`, `X2`) или прокрутку колеса.
- **Проверка схемы без физического перехвата:** Задайте **`Тестовая клавиша`** (например, `D` или `X1`) и запустите узел вручную, чтобы проверить прохождение сообщения через **Коммутатор хоткеев**, **Действие на нажатие**, **Фильтр окон** и **Отладку** даже при выключенном **`Активен`**.

## Порты

### Входы
- **`Возврат / Действие`** (`return`, Object) — Принимает обратные решения по событию (`suppress`, `sendKeys`, `sendMouse`, `sendHardwareId`), сопоставленные по `correlationId`. Сообщения без ожидающего `correlationId` выполняются как прямая аппаратная отправка.

### Выходы
- **`Событие ввода`** (`out`, Object) — Выдаёт пакет `FlowMessage` для каждого перехваченного аппаратного нажатия с полями `correlationId`, `deviceSlot`, `deviceKind`, `hardwareId`, `key` / `button`, `phase` (`down`, `up`, `wheel`, `move`) и скан-кодом.

## Настройка и использование

### Выбор устройства
В Инспекторе откройте блок **Connected Devices**, нажмите **↻ Scan** и выберите нужное устройство. Привязку также можно задать вручную:
- **Тип устройства** (`deviceKind`) — **`Клавиатура`** (`keyboard`) или **`Мышь`** (`mouse`).
- **Hardware ID** (`hardwareIdFilter`) — Регистронезависимая подстрока Hardware ID устройства (например, `VID_xxxx&MI_00`). В отличие от номера слота, Hardware ID сохраняется при переподключении к другим USB-портам и после перезагрузки. Значение `*` выбирает первое устройство указанного типа.
- **Индекс экземпляра** (`instanceIndex`, по умолчанию `1`) — Порядковый номер (начиная с `1`) для различения нескольких одинаковых устройств с идентичным `Hardware ID` (например, две одинаковые клавиатуры: `1` для первой, `2` для второй).
- **Явный слот** (`explicitSlot`, по умолчанию `0`) — При `0` используется поиск по `Hardware ID` + `Индекс экземпляра`. Значения `1–10` (клавиатуры) или `11–20` (мыши) жёстко привязывают узел к конкретному номеру слота драйвера.

### Петля возврата и параметры работы
Для каждого перехватываемого устройства организуйте быстрый возврат решения в **`Возврат / Действие`**:

```text
[Устройство Interception: Событие ввода] ──► [Коммутатор хоткеев / Действие на нажатие] ──► [Устройство Interception: Возврат / Действие]
```

- **Активен** (`active`, по умолчанию `false`) — Включает аппаратный перехват при применении схемы. Выключен по умолчанию ради безопасности.
- **Захват движения мыши** (`captureMove`, по умолчанию `false`) — Актуально только для мышей; не включайте без необходимости.
- **Действие по умолчанию** (`defaultAction`, по умолчанию `Пропускать`) — Резервное решение (`Пропускать` или `Подавлять`) при таймауте или отсутствии флага `suppress`.
- **Таймаут решения (мс)** (`decisionTimeoutMs`, по умолчанию `60`) — Предельное время ожидания ответа по петле возврата.
- **Путь к DLL** (`dllPath`) — Необязательный путь к `interception.dll` (пусто = автопоиск).
- **Тестовая клавиша** (`testKey`, по умолчанию `D`) — Клавиша или кнопка мыши, отправляемая при ручном тестовом запуске узла.

### Советы и безопасность
- Комбинация **`Ctrl+Alt+Pause`** на любой перехваченной клавиатуре или кнопка **`Release`** на виджете узла мгновенно снимают все активные фильтры Interception.
- Предпочитайте привязку по **Hardware ID** (с **Индексом экземпляра** для одинаковых устройств), а не по **Явному слоту**, так как Windows может менять номера слотов Interception после перезагрузки или переподключения USB.
