# Хаб Interception

## Назначение

**Хаб Interception** — центральный многоканальный узел для работы с драйвером ядра Interception. Вместо добавления отдельного узла устройства для каждой клавиатуры и мыши один хаб предоставляет до **4 каналов клавиатур (`Клав. 1`–`Клав. 4`)**, до **4 каналов мышей (`Мышь 1`–`Мышь 4`)**, общий выход мониторинга **`Все события`** и единый порт обратного решения **`Возврат / Действие`**.

Хаб работает по **архитектуре петли возврата (loop-back)**:

```text
[Хаб Interception: Клав. 1 / Мышь 1]
          │  (перехваченное аппаратное событие + correlationId)
          ▼
[Коммутатор хоткеев / Действие на нажатие / Пробник ввода / Фильтр окон / C# Function]
          │  (suppress / pass + необязательная подстановка sendKeys / sendMouse)
          ▼
[Хаб Interception: Возврат / Действие]
```

Когда подключённое устройство генерирует нажатие, цикл драйвера кратковременно удерживает событие (не дольше **`Таймаут решения (мс)`**), отправляет пакет `FlowMessage` через соответствующий выходной порт и ждёт ответа на порту **`Возврат / Действие`**. Получив решение, драйвер подавляет или пропускает исходное нажатие и при необходимости отправляет заменяющие события на аппаратном уровне.

## Типичные сценарии

- **Переназначение нескольких устройств:** Назначьте основную клавиатуру на `Клав. 1`, дополнительный кейпад на `Клав. 2`, а мышь на `Мышь 1`; подключите каждый канал к своему **Коммутатору хоткеев** или цепочке обработки и верните решения в общий вход **`Возврат / Действие`**.
- **Поиск устройств и диагностика:** Включите **`Слушать все устройства`**, подключите **`Все события`** к узлу **Пробник ввода**, а его выход **`Возврат`** — к **`Возврат / Действие`**, чтобы увидеть, какой физический слот и какие клавиши/кнопки на самом деле отправляет любая кнопка устройства.
- **Прямая аппаратная отправка:** Подайте на **`Возврат / Действие`** сообщение без ожидающего `correlationId` (со свойствами `sendKeys` или `sendMouse`), чтобы отправить аппаратный ввод напрямую из другой части схемы.

## Порты

### Входы
- **`Возврат / Действие`** (`return`, Object) — Принимает обратные решения по перехваченным событиям (`suppress`, `sendKeys`, `sendMouse`, `sendHardwareId`, `blockActions`), сопоставленные по `correlationId`, либо выполняет прямую аппаратную отправку.

### Выходы
- **`Все события`** (`all`, Object) — Получает события со всех активных каналов. При включённом параметре **`Слушать все устройства`** перехватывает события со всех подключённых клавиатур и мышей Interception.
- **`Клав. 1` – `Клав. 4`** (`kb1`–`kb4`, Object) — Выделенные выходы для 4 настраиваемых каналов клавиатур.
- **`Мышь 1` – `Мышь 4`** (`mouse1`–`mouse4`, Object) — Выделенные выходы для 4 настраиваемых каналов мышей (кнопки, колесо и опционально движение).

## Настройка и использование

### Список устройств и каналов (`Devices & Hub Channels`)
В панели свойств (Инспекторе) блок **Devices & Hub Channels** показывает все клавиатуры и мыши, обнаруженные драйвером Interception (нажмите **↻ Scan**, чтобы обновить список):
- Поставьте галочку напротив устройства, чтобы автоматически привязать его к следующему свободному каналу (`KB 1–4` или `Mouse 1–4`).
- Или выберите конкретный порт в выпадающем списке в строке устройства (выбор занятого порта аккуратно поменяет привязки местами).
- Если подключено несколько одинаковых устройств с одним Hardware ID, редактор автоматически добавит суффикс экземпляра `#N` (например, `HID\VID_xxxx&PID_xxxx#2`).
- После изменения привязок или переключения **`Активен`** нажмите **Применить** (`Deploy`), чтобы активировать новые фильтры.

### Основные параметры
- **Активен** (`active`, по умолчанию `false`) — Главный переключатель аппаратного перехвата. По умолчанию выключен, чтобы загрузка или редактирование схемы не перехватывали ввод неожиданно.
- **Слушать все устройства** (`monitorAll`, по умолчанию `false`) — Подключает все обнаруженные клавиатуры и мыши и направляет их события в порт **`Все события`**. Удобно для первичной диагностики; в обычной работе отключайте этот режим, чтобы перехватывать только нужные устройства.
- **Действие по умолчанию** (`defaultAction`, по умолчанию `Пропускать`) — Резервное действие, если ответ по петле возврата не пришёл вовремя или не содержит явного флага `suppress`:
  - **Пропускать** (`pass`) — Пропускает исходное событие в Windows (наиболее безопасный вариант).
  - **Подавлять** (`suppress`) — Отбрасывает исходное событие, если схема явно не указала `suppress = false`.
- **Фильтры Клав. 1–4 / Мыши 1–4** (`kb1Filter`..`mouse4Filter`) — Заполняются автоматически списком устройств или вручную: подстрокой Hardware ID, селектором экземпляра `HWID#N` либо явным номером слота (`1–10` для клавиатур, `11–20` для мышей).
- **Захват движения мыши** (`captureMove`, по умолчанию `false`) — Включает высокочастотные события относительного перемещения курсора. Оставляйте выключенным, если схеме не нужны дельты координат.
- **Таймаут решения (мс)** (`decisionTimeoutMs`, по умолчанию `60`) — Максимальное время ожидания ответа по петле возврата до применения **`Действия по умолчанию`**.
- **Путь к DLL** (`dllPath`) — Необязательный явный путь к `interception.dll` (пусто = автопоиск).

### Безопасность и аварийное отключение
- **Аварийная комбинация (`Ctrl+Alt+Pause`):** Отслеживается непосредственно в нативном цикле драйвера на любой перехваченной клавиатуре. Нажатие левого или правого `Ctrl` + левого или правого `Alt` + `Pause` мгновенно снимает все фильтры Interception и возвращает весь ввод напрямую в Windows.
- **Кнопка `Release`:** Расположена прямо на виджете узла и одним кликом выполняет то же аварийное снятие всех фильтров.
- **Совет:** Всегда замыкайте путь возврата (например, `Коммутатор хоткеев -> Возврат` или `Пробник ввода -> Возврат`) обратно в **`Возврат / Действие`**, чтобы каждое нажатие обрабатывалось мгновенно без ожидания **`Таймаута решения (мс)`**.
